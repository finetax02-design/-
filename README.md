# 세무 자동분개 시스템

위하고(WEHAGO) / 세무사랑Pro의 국세청 수집자료 중 자동분개되지 않는 건을
계정과목 자동 분개 + 자동 전송까지 처리하는 것이 목표.

## 현재 단계

1단계 — 자동화 룰의 커버리지 실측.
아직 엔진은 없고, 과거 분개 이력에서 어떤 룰이 몇 % 를 커버하는지 재는 분석기만 있다.

## src/analyze.py

위하고 T > 전자세금계산서 화면의 엑셀 내려받기 파일을 읽어,
`거래처코드 -> 계정과목` 룰(L1)이 실제로 몇 %를 맞추는지 leave-one-out으로 실측한다.

```
pip install openpyxl
python src/analyze.py 내려받은파일.xlsx --out rules.json
```

리포트 항목:

| # | 내용 |
|---|---|
| 1 | 계정과목 분포 |
| 2 | 공제구분(과세/불공) 월별 추이 |
| 3 | 거래처별 계정과목 집중도 — 단일계정 vs 다계정 |
| 4 | L1 룰 실측 정확도 (적중 / 오답 / 이력없음) |
| 5 | 이력 없는 신규 거래처 목록 |
| 6 | 미분개분이 기존 룰로 커버되는 비율 |

`rules.json` 은 거래처코드별 계정과목 / 대변계정 / 공제구분 룰 테이블이며,
이후 분개 엔진의 L1 계층 입력으로 그대로 쓴다.

여러 기수를 합쳐 보려면 파일을 여러 개 넘기면 된다.

```
python src/analyze.py 2025_1기.xlsx 2025_2기.xlsx 2026_1기.xlsx
```

## src/nts_join.py

국세청 전자세금계산서 원본(.xls)과 위하고 분개결과(.xlsx)를 붙여
`사업자등록번호 -> 계정과목` 룰을 만든다.

위하고 화면 엑셀에는 위하고 내부 거래처코드만 있고 사업자등록번호가 없다.
실제 운영에서 들어오는 입력은 국세청 원본이므로, 사업자등록번호를 키로
쓰려면 두 파일을 조인해야 한다.

```
pip install openpyxl xlrd
python src/nts_join.py --nts 국세청원본.xls --wehago 위하고내역.xlsx --out dataset.csv
```

조인 키는 `(작성일자 MM-DD, 공급가액, 세액)`. 승인번호가 위하고 엑셀에
없어서 금액+일자로 붙이며, 실측 조인율은 100% 였다.

`dataset.csv` 는 국세청 원본 필드(사업자번호/상호/주소/품목명)에
위하고 분개 결과(계정과목/대변계정/공제구분)를 붙인 학습 데이터다.

## 컬럼명이 다를 때

위하고 버전에 따라 엑셀 컬럼명이 바뀔 수 있다.
`src/analyze.py` 상단 `COL` 딕셔너리의 값만 실제 헤더에 맞춰 고치면 된다.

## 데이터 취급

고객사 과세정보이므로 실데이터 파일은 저장소에 커밋하지 않는다.
분석은 로컬에서 실행하고 집계 결과만 공유한다.
