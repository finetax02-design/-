# 위하고 자동분개 - 어떻게 동작하는가

여러 번의 시행착오 끝에 찾아낸 경로를 기록해 둔다.
화면이 바뀌거나 다른 고객사에서 막혔을 때 여기서부터 다시 보면 된다.

## 통하는 경로

```
크롬열기.bat 으로 띄운 크롬 (원격 디버깅 포트 9222)
    ↓ connect_over_cdp 로 붙기만 한다
전자세금계산서 화면 (smarta.wehago.com/#/smarta/account/SAAC0103)
    ↓
전표 목록 그리드에서 전 건 읽기
    ↓
과거 이력에서 계정 규칙 학습
    ↓
빈 칸으로 커서 이동 → F2 → 코드도움 팝업
    ↓
팝업 목록(계정과목 마스터 839개)에서 코드로 줄 찾기 → 그 줄 지정
    ↓
확인(enter) 버튼 클릭
    ↓
값 반영, 차변·대변이 모두 차면 전표상태가 미추천에서 확정가능으로
```

## 막혔던 것과 이유

| 시도 | 결과 | 이유 |
|---|---|---|
| Playwright 가 브라우저를 띄움 | 화면이 빈 채로 뜸 | 자동화된 브라우저를 감지해 렌더링을 안 한다 |
| DOM 에서 전표 행 찾기 | 행이 없음 | RealGrid 가 canvas 에 그린다 |
| `RealGrid.getGridInstance()` | 없음 | 인스턴스가 전역에 노출되지 않는다 |
| React fiber 타고 찾기 | 못 찾음 | props/state 에 없다 |
| `setValue` 로 값 쓰기 | 값은 들어가나 전표상태 그대로 | 위하고의 편집 흐름이 시작되지 않는다 |
| `showEditor()` | 편집기가 안 열림 | `editOptions.editWhenFocused = false` |
| 계정코드 칸에 직접 쓰기 | 불가 | `cd_acctit_cha` 는 `editable=false, visible=false` |
| `keyboard.type()` 로 한글 입력 | 글자가 뒤섞임 (`의약품` → `약품의`) | 키 이벤트가 한글 조합 처리와 충돌 |
| 팝업 검색칸 클릭 | 시간 초과 | 필요 없다. 마스터에 전부 있어 검색을 안 해도 된다 |
| 팝업에서 Enter 키 | 안 먹음 | 키보드 초점이 팝업 그리드에 없다. 확인 버튼을 클릭해야 한다 |

## 그리드 잡는 법

전역에 안정된 경로가 없다. `window.Grids.CellIndex.$_temp._grid` 는
마지막에 건드린 그리드를 가리키는 임시 자리라 실행할 때마다 달라진다.

그래서 `window` 에서 깊이 9까지 훑어 `getColumns` 와 `getValues` 를 가진
객체를 모두 모은 뒤 **컬럼 이름으로 구분**한다.

- 전표 목록: `nm_acctit_cha` 를 가진 그리드 (58컬럼)
- 코드도움 팝업: `cd_acctit` 와 `nm_acctit` 을 가진 그리드 (11컬럼, 839행)

경로를 외워 쓰지 않는다. 매번 찾고 매번 검증한다.

## 알아낸 필드

| 필드 | 뜻 | 값 |
|---|---|---|
| `ty_jungstat` | 전표상태 | 1=확정가능 2=전표확정 5=미추천 |
| `ty_mth2` | 유형 | 51=과세 54=불공 |
| `cd_notdedct` | 불공제코드 | 불공 건과 정확히 일치 |
| `nm_acctit_cha` / `cd_acctit_cha` | 차변 계정명 / 코드 | 이름만 편집 가능 |
| `nm_acctit_dae` / `cd_acctit_dae` | 대변 계정명 / 코드 | 이름만 편집 가능 |
| `no_bisocial` | 공급자 사업자등록번호 | 규칙의 열쇠 |
| `nm_good` | 품명 | 신규 거래처일 때 쓴다 |

**빈 칸 판정은 이름이 아니라 코드로 한다.** 이름칸에는 코드가 `null` 일 때
`미추천` 이라는 글자가 들어 있어서, 이름으로 판정하면 비어 있는데도
채워진 것으로 본다.

**미추천 건이라고 차변과 대변이 둘 다 빈 것이 아니다.** 한쪽만 빈 경우가
대부분이고, 위하고는 둘 다 차야 전표상태를 풀어준다.

## 화면 주소

```
smarta.wehago.com/#/smarta/account/SAAC0103
    ?cd_com=<고객사>&gisu=<기수>&searchData=<시작YYYYMMDD><끝YYYYMMDD>
```

주소만 바꾸면 메뉴를 타지 않고 고객사와 기간을 지정해 열 수 있다.

## 규칙

계정과목은 같은 화면의 과거 이력에서 배운다. 별도 파일이 필요 없다.

1. 같은 사업자등록번호의 과거 계정
2. 같은 품명의 과거 계정 (오더번호·날짜·숫자를 지우고 비교)
3. 대변만, 그 고객사에서 가장 많이 쓰는 대변

차변을 판단하지 못하면 그 줄은 손대지 않는다.

실측 정확도 (2026년 상반기)

| | 오벨피부과 (의원) | (주)다원 (제조) |
|---|---|---|
| 사업자번호 규칙 | 91.9% | 54.6% |
| 품명 규칙 | 0.4% | 41.2% |
| 자동 처리 | 92.3% | 95.8% |
| 계정과목 정확도 | 100% | 99.2% |

업종에 따라 두 규칙의 비중이 정반대로 갈린다. 둘 다 필요하다.

## 공제 불공제 전환

유형 칸 `ty_mth2` 는 `lookupDisplay=true` 인 코드 컬럼이다.
값과 이름이 컬럼 정의에 들어 있다. 51=과세 54=불공.

전환 방법

```
setValue(row, 'ty_mth2', '54') + onCellEdited(g, row, row, 컬럼번호)
    ↓
불공제 사유 라디오 팝업이 뜬다 (순수 HTML)
    LUXRa0 ~ LUXRa9, LUXRaA, LUXRaB  — 코드와 1:1 대응
    0 토지의 자본적 지출관련   3 비영업용 소형승용차 구입 및 유지
    4 면세사업과 관련된 분     5 공통매입세액 안분계산서 분
    9 접대비 관련 매입세액     ...
    ↓
원하는 사유 라디오를 클릭하고 확인 버튼을 누른다
```

**팝업을 esc 로 닫으면 취소가 아니라 기본값 4(면세사업관련)가 들어간다.**
위하고 코드의 `tyMth54: ... ?? "4"` 때문이다.
팝업이 뜨면 반드시 사유를 고르고 확인까지 해야 한다.
중간에 멈추면 엉뚱한 사유가 남는다.

`cd_notdedct` 는 `editable=false, visible=false` 라 직접 쓸 수 없다.
반드시 이 팝업을 거쳐야 한다.

### 팝업마다 버튼 이름이 다르다

| 팝업 | 확정 버튼 |
|---|---|
| 계정과목 코드도움 | `확인(enter)` |
| 불공제사유선택 | `선택(enter)` |

한쪽 이름만 찾으면 못 누르고, 그러면 Enter 키로 넘어가 그때 선택돼 있던
값이 확정된다. 불공제사유는 기본값이 4 라 4 가 들어간다.

### 사유 라디오는 같은 목록이 두 벌 있다

화면에 `input[type=radio]` 가 37개나 있고, 불공제 사유 12개짜리 목록이
**두 벌** 존재한다.

| 묶음 | rect | 정체 |
|---|---|---|
| 앞쪽 LUXRa0~B | `(0,0) 0x0` | 화면에 없는 껍데기 |
| 뒤쪽 LUXRa0~B | `(354,381)~(354,547) 13x13` | 실제로 보이는 것 |

글자만 보고 첫 번째를 고르면 껍데기를 잡는다. 좌표가 `(0,0)` 이라
클릭이 화면 왼쪽 맨 위 구석으로 간다.

**반드시 rect 크기가 0 이 아닌 것만 대상으로 해야 한다.**

선택 여부를 확인할 때도 마찬가지다. 문서 전체에서 첫 번째로 체크된
라디오를 읽으면 거래처 필터의 `tradeRadioBtnA`("전체") 같은
전혀 다른 라디오를 보게 된다. 글자가 `0.` `5.` `A.` 처럼 코드로 시작하고
크기가 있는 것만 걸러서 봐야 한다.

### 라디오는 숨은 입력칸을 누르면 안 된다

`input[type=radio]` 는 `tabindex="-1"` 로 숨겨져 있고 눈에 보이는 것은
옆의 글자다. 숨은 입력칸에 `click()` 을 보내면 화면이 반응하지 않는다.
글자를 감싼 요소의 좌표를 구해 **진짜 마우스로 클릭**해야 한다.

누른 뒤에는 원하는 사유가 실제로 선택됐는지 확인하고, 아니면 확정하지 말고
유형을 과세로 되돌린다. 그냥 두면 기본값 4 가 남는다.

## 지키는 것

- 전송(F3)은 절대 부르지 않는다. 전송은 사람이 한다.
- 칸마다 거래처명과 공급가액을 대조하고 다르면 건너뛴다.
- 쓰기 전후 코드를 비교해 실제로 바뀌었을 때만 성공으로 센다.
- 한 칸 먼저 하고 확인한 뒤에 나머지로 넘어간다.
- 한 칸이라도 실패하면 즉시 멈춘다.
