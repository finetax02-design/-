# 위하고 자동분개 - 어떻게 동작하는가

여러 번의 시행착오 끝에 찾아낸 경로를 기록해 둔다.
화면이 바뀌거나 다른 고객사에서 막혔을 때 여기서부터 다시 보면 된다.

## 통하는 경로

```
크롬열기.bat 으로 띄운 크롬 (원격 디버깅 포트 9222)
    ↓ connect_over_cdp 로 붙기만 한다
전자세금계산서 화면 (smarta.wehago.com/#/smarta/account/SAAC0103)
    ↓
전표 목록 그리드에서 전 건 읽기
    ↓
과거 이력에서 계정 규칙 학습
    ↓
빈 칸으로 커서 이동 → F2 → 코드도움 팝업
    ↓
팝업 목록(계정과목 마스터 839개)에서 코드로 줄 찾기 → 그 줄 지정
    ↓
확인(enter) 버튼 클릭
    ↓
값 반영, 차변·대변이 모두 차면 전표상태가 미추천에서 확정가능으로
```

## 막혔던 것과 이유

| 시도 | 결과 | 이유 |
|---|---|---|
| Playwright 가 브라우저를 띄움 | 화면이 빈 채로 뜸 | 자동화된 브라우저를 감지해 렌더링을 안 한다 |
| DOM 에서 전표 행 찾기 | 행이 없음 | RealGrid 가 canvas 에 그린다 |
| `RealGrid.getGridInstance()` | 없음 | 인스턴스가 전역에 노출되지 않는다 |
| React fiber 타고 찾기 | 못 찾음 | props/state 에 없다 |
| `setValue` 로 값 쓰기 | 값은 들어가나 전표상태 그대로 | 위하고의 편집 흐름이 시작되지 않는다 |
| `showEditor()` | 편집기가 안 열림 | `editOptions.editWhenFocused = false` |
| 계정코드 칸에 직접 쓰기 | 불가 | `cd_acctit_cha` 는 `editable=false, visible=false` |
| `keyboard.type()` 로 한글 입력 | 글자가 뒤섞임 (`의약품` → `약품의`) | 키 이벤트가 한글 조합 처리와 충돌 |
| 팝업 검색칸 클릭 | 시간 초과 | 필요 없다. 마스터에 전부 있어 검색을 안 해도 된다 |
| 팝업에서 Enter 키 | 안 먹음 | 키보드 초점이 팝업 그리드에 없다. 확인 버튼을 클릭해야 한다 |

## 그리드 잡는 법

전역에 안정된 경로가 없다. `window.Grids.CellIndex.$_temp._grid` 는
마지막에 건드린 그리드를 가리키는 임시 자리라 실행할 때마다 달라진다.

그래서 `window` 에서 깊이 9까지 훑어 `getColumns` 와 `getValues` 를 가진
객체를 모두 모은 뒤 **컬럼 이름으로 구분**한다.

- 전표 목록: `nm_acctit_cha` 를 가진 그리드 (58컬럼)
- 코드도움 팝업: `cd_acctit` 와 `nm_acctit` 을 가진 그리드 (11컬럼, 839행)

경로를 외워 쓰지 않는다. 매번 찾고 매번 검증한다.

## 알아낸 필드

| 필드 | 뜻 | 값 |
|---|---|---|
| `ty_jungstat` | 전표상태 | 1=확정가능 2=전표확정 5=미추천 |
| `ty_mth2` | 유형 | 51=과세 54=불공 |
| `cd_notdedct` | 불공제코드 | 불공 건과 정확히 일치 |
| `nm_acctit_cha` / `cd_acctit_cha` | 차변 계정명 / 코드 | 이름만 편집 가능 |
| `nm_acctit_dae` / `cd_acctit_dae` | 대변 계정명 / 코드 | 이름만 편집 가능 |
| `no_bisocial` | 공급자 사업자등록번호 | 규칙의 열쇠 |
| `nm_good` | 품명 | 신규 거래처일 때 쓴다 |

**빈 칸 판정은 이름이 아니라 코드로 한다.** 이름칸에는 코드가 `null` 일 때
`미추천` 이라는 글자가 들어 있어서, 이름으로 판정하면 비어 있는데도
채워진 것으로 본다.

**미추천 건이라고 차변과 대변이 둘 다 빈 것이 아니다.** 한쪽만 빈 경우가
대부분이고, 위하고는 둘 다 차야 전표상태를 풀어준다.

smarta.wehago.com/#/smarta/account/SAAC0103
    ?cd_com=<고객사>&gisu=<기수>&searchData=<시작YYYYMMDD><끝YYYYMMDD>

주소만 바꾸면 메뉴를 타지 않고 고객사와 기간을 지정해 열 수 있다.

## 규칙

계정과목은 같은 화면의 과거 이력에서 배운다. 별도 파일이 필요 없다.

1. 같은 사업자등록번호의 과거 계정
2. 같은 품명의 과거 계정 (오더번호·날짜·숫자를 지우고 비교)
3. 대변만, 그 고객사에서 가장 많이 쓰는 대변

차변을 판단하지 못하면 그 줄은 손대지 않는다.

실측 정확도 (2026년 상반기)

| | 오벨피부과 (의원) | (주)다원 (제조) |
|---|---|---|
| 사업자번호 규칙 | 91.9% | 54.6% |
| 품명 규칙 | 0.4% | 41.2% |
| 자동 처리 | 92.3% | 95.8% |
| 계정과목 정확도 | 100% | 99.2% |

업종에 따라 두 규칙의 비중이 정반대로 갈린다. 둘 다 필요하다.

## 공제 불공제 전환

유형 칸 `ty_mth2` 는 `lookupDisplay=true` 인 코드 컬럼이다.
값과 이름이 컬럼 정의에 들어 있다. 51=과세 54=불공.

전환 방법

```
setValue(row, 'ty_mth2', '54') + onCellEdited(g, row, row, 컬럼번호)
    ↓
불공제 사유 라디오 팝업이 뜬다 (순수 HTML)
    LUXRa0 ~ LUXRa9, LUXRaA, LUXRaB  — 코드와 1:1 대응
    0 토지의 자본적 지출관련   3 비영업용 소형승용차 구입 및 유지
    4 면세사업과 관련된 분     5 공통매입세액 안분계산서 분
    9 접대비 관련 매입세액     ...
    ↓
원하는 사유 라디오를 클릭하고 확인 버튼을 누른다
```

**팝업을 esc 로 닫으면 취소가 아니라 기본값 4(면세사업관련)가 들어간다.**
위하고 코드의 `tyMth54: ... ?? "4"` 때문이다.
팝업이 뜨면 반드시 사유를 고르고 확인까지 해야 한다.
중간에 멈추면 엉뚱한 사유가 남는다.

`cd_notdedct` 는 `editable=false, visible=false` 라 직접 쓸 수 없다.
반드시 이 팝업을 거쳐야 한다.

### 팝업마다 버튼 이름이 다르다

| 팝업 | 확정 버튼 |
|---|---|
| 계정과목 코드도움 | `확인(enter)` |
| 불공제사유선택 | `선택(enter)` |

한쪽 이름만 찾으면 못 누르고, 그러면 Enter 키로 넘어가 그때 선택돼 있던
값이 확정된다. 불공제사유는 기본값이 4 라 4 가 들어간다.

### 사유 라디오는 같은 목록이 두 벌 있다

화면에 `input[type=radio]` 가 37개나 있고, 불공제 사유 12개짜리 목록이
**두 벌** 존재한다.

| 묶음 | rect | 정체 |
|---|---|---|
| 앞쪽 LUXRa0~B | `(0,0) 0x0` | 화면에 없는 껍데기 |
| 뒤쪽 LUXRa0~B | `(354,381)~(354,547) 13x13` | 실제로 보이는 것 |

글자만 보고 첫 번째를 고르면 껍데기를 잡는다. 좌표가 `(0,0)` 이라
클릭이 화면 왼쪽 맨 위 구석으로 간다.

**반드시 rect 크기가 0 이 아닌 것만 대상으로 해야 한다.**

선택 여부를 확인할 때도 마찬가지다. 문서 전체에서 첫 번째로 체크된
라디오를 읽으면 거래처 필터의 `tradeRadioBtnA`("전체") 같은
전혀 다른 라디오를 보게 된다. 글자가 `0.` `5.` `A.` 처럼 코드로 시작하고
크기가 있는 것만 걸러서 봐야 한다.

### 라디오는 숨은 입력칸을 누르면 안 된다

`input[type=radio]` 는 `tabindex="-1"` 로 숨겨져 있고 눈에 보이는 것은
옆의 글자다. 숨은 입력칸에 `click()` 을 보내면 화면이 반응하지 않는다.
글자를 감싼 요소의 좌표를 구해 **진짜 마우스로 클릭**해야 한다.

누른 뒤에는 원하는 사유가 실제로 선택됐는지 확인하고, 아니면 확정하지 말고
유형을 과세로 되돌린다. 그냥 두면 기본값 4 가 남는다.

## 불공제사유 라디오는 포기한다 - 일괄변경으로 우회

라디오를 직접 고르는 것은 여섯 가지 방법으로 모두 실패했다.
좌표 클릭, 글자 클릭, 포커스+스페이스, force 클릭, `el.click()`,
네이티브 setter + input/change 이벤트, 포인터 이벤트 흉내.
진단해보면 덮인 것도 없고 좌표도 맞고 `visibility` 도 정상인데
선택이 되돌아간다. 부품 내부에서 되돌리는 것으로 보이며 더 파도 얻을 게 없다.

**대신 위하고의 일괄변경 기능을 쓴다. 라디오를 아예 누를 일이 없어진다.**

### 원리

일괄변경은 **현재 줄을 본보기로 삼아 체크한 줄들에 그대로 베낀다.**
그래서 사유가 정확히 들어간 불공 줄 하나를 현재 줄로 만들어 두면
체크한 줄들이 그 줄과 같은 유형(불공) + 같은 사유로 한 번에 바뀐다.

    1  사유가 맞는 불공 줄 하나를 손으로 만들어 둔다   (본보기 줄)
    2  바꿀 줄들을 전부 체크            (checkAll(false) 후 checkItems)
    3  본보기 줄의 '유형' 칸을 잡는다   (setCurrent, column: 'ty_mth2')
    4  오른쪽 맨 아래 '일괄변경' > '전체일괄변경'
    5  불공제사유 창이 뜬다. 본보기의 사유가 미리 골라진 채로 뜬다
    6  골라진 사유를 대조하고 '선택(enter)'

### 어느 칸을 잡았는지가 곧 '무엇을 바꿀지' 다

3번이 핵심이다. 별도의 선택 화면이 있는 것이 아니라
**현재 잡은 칸이 속한 열이 바꿀 항목**이 된다.

거래처 칸을 잡은 채로 실행하면 이 안내만 뜬다.

    [품명] [유형] [차변계정] [대변계정] [관리] [전표상태] 선택후, 실행하세요.

바꿀 수 있는 열은 저 여섯 개뿐이다. 유형을 바꾸려면 `ty_mth2` 칸을 잡아야 한다.

### setCurrent 로는 안 된다. 진짜로 눌러야 한다

`setCurrent({column:'ty_mth2'})` 를 하면 파란 테두리는 그 칸으로 옮겨간다.
사람 눈에는 똑같아 보인다. 그런데 일괄변경 확인창의 변경내용이 비어서 나온다.

    변경항목 | 변경내용 | 건수
            |         |          <- 비어 있다

위하고는 그리드 이벤트를 듣고 자기 쪽에 기억해 두는데
`setCurrent` 는 그 이벤트를 일으키지 않는다.
`setValue` 로 값을 바꿔도 전표상태가 안 따라와 `onCellEdited` 를 직접
불러야 했던 것과 같은 일이다.

**칸의 화면 좌표는 `getCellBounds` 가 준다.** 그리드 안쪽 좌표가 아니라
화면 좌표를 그대로 주므로 그 자리를 그냥 누르면 된다.

    g.setTopItem(줄)                        // 먼저 그 줄이 보이게 한다
    const b = g.getCellBounds(줄, 'ty_mth2')
    // b = {x:367, y:241, width:40, height:28}
    page.mouse.click(b.x + b.width/2, b.y + b.height/2)

누른 뒤 `getCurrent()` 가 `{itemIndex:줄, fieldName:'ty_mth2'}` 인지 본다.
사람이 손으로 클릭했을 때와 글자 하나 다르지 않아야 한다.

### 사유 창의 라디오는 애초에 라디오가 아니다

낱낱이 뜯어보니 이랬다.

- **name 이 없다.** 한 무리로 묶이지 않으니 여러 개가 동시에 체크된다.
  실제로 `4` 와 `5` 가 둘 다 체크되어 있었다. 속값은 4, 표시용은 5 다.
- **두 벌이다.** 12개는 `0,0 0x0` 껍데기, 12개는 진짜 (380,382~).
  껍데기는 `.click()` 에 반응해 체크가 하나 더 늘어난다.
- **리액트가 옛 판이다.** `__reactProps$` 가 없고 `__reactInternalInstance$` 만 있다.
  그래서 onChange 를 찾을 수 없다.
- **진짜 라디오는 마우스로 눌러도 꿈쩍하지 않는다.**
  `elementFromPoint` 로 보면 `span.label_text` 가 나와 가려진 것도 없는데 그렇다.

여섯 가지를 다 시험했다. 라벨 좌표, 입력칸 좌표, `label.click()`,
`input.click()`, 네이티브 setter + change, 리액트 onChange.
**하나도 통하지 않았다.** 이 창은 그만 두는 것이 맞다.

### 사유는 창을 거치지 않고 칸에 직접 넣는다 (이것이 답이다)

창을 붙들고 있을 까닭이 없다. 유형만 일괄변경으로 얻고 사유는 따로 넣는다.

    1  일괄변경으로 유형을 불공으로 바꾼다
    2  사유 창이 뜨면 그대로 확인한다. 사유가 4 로 들어가도 상관없다
    3  유형이 다 바뀌었는지 먼저 확인한다. 안 바뀌었으면 사유는 건드리지 않는다
    4  줄마다 사유를 칸에 직접 넣는다

    g.setValue(줄, 'cd_notdedct', '5')
    g.onCellEdited(g, 줄, 줄, 36)      // 36 은 cd_notdedct 열 자리

`cd_notdedct` 는 `editable=false, visible=false` 인 숨은 칸인데도 들어간다.
계정과목 때 `setValue` 만으로는 전표상태가 안 따라와 `onCellEdited` 를
직접 불러 풀었던 것과 같은 길이다. 전표상태도 1(확정가능)로 제대로 선다.

    4번째 (주) 라티스  사유 4 -> 5  (열자리 36, 전표상태 1)

열 자리는 박아두지 말고 그때그때 `getColumns()` 에서 찾는다.

### 사유 창은 보이는 것과 속이 다르다

창이 뜨면 본보기 줄의 사유가 이미 골라진 것처럼 보인다.
`[O]5.공통매입세액 안분계산서 분` 이라고 표시까지 된다.
그런데 그대로 선택을 누르면 **4 가 들어간다.**

보이는 표시와 위하고가 실제로 쓰는 값이 서로 다른 것이다.
표시는 현재 줄에서 가져와 그려 놓고, 실제로 쓰는 값은 따로 `"4"` 로 두었다가
**라디오가 바뀔 때만** 갱신하는 것으로 보인다.
이미 표시가 있는 자리를 눌러봐야 '바뀜' 이 일어나지 않으니 값은 4 그대로다.

낱건 전환이 늘 4 로 끝난 것도, 표시는 5 인데 4 가 들어간 것도 모두 이것이다.

**다른 사유를 한 번 거쳐 갔다가 바라던 사유로 돌아온다.**

    4 를 누른다  -> 표시가 4 로 옮겨졌는지 읽어 확인
    5 를 누른다  -> 표시가 5 로 옮겨졌는지 읽어 확인
    그제서야 선택(enter)

두 번 다 '바뀜' 이 일어나므로 위하고가 알아듣는다.
한 번이라도 표시가 안 옮겨지면 선택을 누르지 않고 멈춘다.
esc 는 취소가 아니라 기본값을 확정하므로 절대 쓰지 않는다.
멈출 때는 사람이 화면의 취소(esc) 단추를 누르게 한다.

### 본보기 줄은 규칙표와 어긋나지 않는 것만 쓴다

사유가 잘못 들어간 줄이 다음 실행에서 본보기로 뽑히면 잘못이 퍼진다.
거래처의 규칙과 줄의 사유가 다르면 본보기 후보에서 뺀다.

### 체크 개수는 한 가지 방법만 믿으면 안 된다

`getCheckedItemIndices()` 가 0 을 돌려주는데 화면 아래에는 `1건 선택됨`
이 떠 있는 일이 있었다. 세는 방법을 셋 다 써서 가장 큰 값을 본다.

    getCheckedItemIndices / getCheckedRows / getCheckedItems
    isCheckedItem 으로 한 줄씩 물어보기
    화면 아래 '선택됨 N건' 글자 읽기

본보기가 하나뿐이라 **사유는 한 번에 하나씩만** 처리된다.
사유 3, 4, 5 를 각각 따로 돌린다.

화면에 그 사유의 불공 줄이 하나도 없으면 본보기가 없어서 못 한다.
그럴 때는 사람이 한 줄만 손으로 바꾼 뒤 실행하면 나머지는 자동이다.

### 체크는 그리드가 관리한다

체크박스는 캔버스에 그려지지만 그리드 API 로 다룰 수 있다.

    g.checkAll(false)            // 또는 resetCheckables(false)
    g.checkItems([52,55,56], true)
    g.getCheckedItemIndices()    // 확인용

`checkItem, checkItems, checkAll, getCheckedRows, getCheckedItems,
resetCheckables, applyCheckables, setCheckBar, isCheckedItem` 을 쓸 수 있다.
요청한 줄 수와 실제 체크된 줄 수가 다르면 진행하지 않는다.

### 단추를 찾을 때

'일괄변경' 은 글자가 정확히 같은 것만 고른다. 그냥 포함으로 찾으면
'전체일괄변경', '적요코드일괄변경' 까지 걸린다.
글자를 가진 가장 안쪽 요소를 고르고, 크기가 0 이 아닌 것만 남기고,
여러 개면 아래쪽 것을 고른다 (일괄변경은 화면 오른쪽 맨 아래, 전표전송 옆).

확인창의 단추 이름은 `확인(Enter)` 이다. 계정과목 팝업의 `확인(enter)` 와
대소문자가 다르므로 둘 다 시도한다.

### 확인창을 반드시 대조한다

'위의 항목을 일괄변경 하시겠습니까?' 창의 표에서 건수를 읽어
체크한 건수와 같은지, '불공' 이라는 말이 있는지 확인한 뒤에만 확인을 누른다.
하나라도 어긋나면 누르지 않고 멈춘다.

바꾼 뒤에는 목록을 다시 읽어 `ty_mth2=54`, `cd_notdedct=<사유>` 가
실제로 들어갔는지, 줄이 밀리지 않았는지 거래처명으로 대조한다.

### 확인창의 변경내용은 글자가 아니라 입력칸의 값이다

전체일괄변경 확인창의 표를 읽으면 이렇게 비어 보인다.

    변경항목 | 변경내용 | 건수
            |         |

그런데 화면을 눈으로 보면 `과세유형 | 불공 | 1` 이 멀쩡히 들어 있다.
8초를 기다려도 마찬가지다. 늦게 채워지는 것이 아니라
**칸 안에 `<input>` 이 들어 있고 값이 거기 담겨 있기 때문**이다.
`innerText` 로는 영원히 안 보인다.

    const 칸글자 = c => {
      let t = (c.innerText || '').trim();
      if (t) return t;
      const 값 = [];
      for (const i of c.querySelectorAll('input,textarea')) if (i.value) 값.push(i.value);
      return 값.join(' ').trim();
    };

화면에서 회색 칸처럼 보이면 입력칸을 의심한다.

### 창은 먼저 뜨고 알맹이는 나중에 채워지기도 한다

**표의 머리줄 아래에 글자가 들어올 때까지 되풀이해 읽는다.**
사유 라디오가 보이거나 '대상이 없습니다' 가 뜨는 것도 다 채워진 것으로 친다.

### 사유 창은 확인 앞에 뜰 수도 뒤에 뜰 수도 있다

어느 쪽이든 되도록 확인 앞뒤로 두 번 살펴본다.


## 크롬에 붙어 있으면 크롬이 멎는다

Playwright 로 크롬에 붙은 채로 가만히 지켜보기만 해도
**새 화면이 뜨는 것을 붙잡아 버린다.**
첫 고객사는 잘 들어가지는데 두 번째 고객사로 들어가려면 멎고,
프로그램을 닫아야 풀린다.

값을 바꾸는 일(계정과목 채우기, 일괄변경)은 짧게 붙었다 떨어지므로 괜찮다.
문제는 **오래 켜두고 지켜보는 일**이다.

지켜보기만 할 때는 붙지 말고 **밖에서 물어본다.**

    http://localhost:9222/json

크롬이 열려 있는 탭의 제목과 주소를 그냥 알려준다.
붙는 것이 아니라 물어보는 것이라 크롬이 하는 일을 조금도 방해하지 않는다.

고객사명은 탭 제목에 들어 있다.

    "전자세금계산서(2기) - 오벨피부과의원"
       화면        기수      고객사명

주소에서 `cd_com`, `gisu`, `cno`, `yminsa` 를 뽑고 제목에서 이름을 뽑으면
화면을 건드리지 않고도 고객사 목록을 만들 수 있다.


## 고객사는 주소로 바꿀 수 없다

주소에 `cd_com`, `gisu`, `cno` 가 다 들어 있어서 그것만 갈면 될 줄 알았다.
안 된다.

    주소를 갈아끼움  -> 주소창만 바뀌고 화면은 25초 내내 앞 고객사 그대로
    새로고침까지 함  -> 조은세무법인. 고객사가 아예 풀린다

`#` 뒤가 바뀌어도 화면이 다시 그려지지 않고, 처음부터 새로 열면
고객사가 안 잡힌 채로 뜬다. 고객사는 **수임처 화면에서 회계를 눌러야** 잡힌다.

그래서 순회는 주소를 가는 것이 아니라
**수임처 화면에서 이름으로 찾아 회계를 누르는** 것으로 한다.
사람이 손으로 하는 그 동작 그대로다. 이 길은 된다.

### 처음 열릴 때 주소는 이름이 다르다

회계를 누르면 **새 탭**이 열리는데 주소가 이렇게 생겼다.

    smarta.wehago.com/#/smarta/account?wehagoT
      &cNum=5583734          <- 목록의 cno
      &taxNum=9009
      &taxAccounts=4         <- 목록의 gisu
      &taxDate=2026010120261231

`cd_com` 이 없다. 전자세금계산서 화면까지 들어가야 `cd_com` 이 붙는다.
그러니 새로 열린 탭을 알아볼 때는 `cNum` 으로 찾아야 한다.

**고객사를 열 때마다 탭이 하나씩 늘어난다.**
순회할 때는 한 고객사를 마치면 그 탭을 닫아야 한다.

### 메뉴는 이름 통째로 보고 골라야 한다

메뉴 검색칸에 글자를 넣으면 겹치는 부분만 따로 표시된다.

    전자세금계산서발급세액공제신고서
    ~~~~~~~~~~~~~~                 <- 이 조각만 따로 표시된다

'글자가 정확히 같은 가장 안쪽 것' 을 찾으면 이 조각이 잡힌다.
눌러도 부모에게 전해져 **엉뚱한 메뉴로 들어간다.**
줄 통째의 글자를 읽어 딱 `전자세금계산서` 인 줄만 눌러야 한다.

### 화면이 바뀌어도 주소는 그대로다

메뉴로 화면을 옮겨도 주소가 `SAAC0103` 으로 바뀌지 않는 때가 있다.
그러니 도착했는지는 주소로 보지 말고 **전표 목록이 잡히는지**로 본다.
`nm_acctit_cha` 를 가진 그리드가 잡히면 전자세금계산서 화면이다.

**다만 건수로 따지면 안 된다.** 조회를 누르기 전에는 자료가 0건이다.
틀이 있느냐만 본다. 자료가 있느냐는 조회를 누른 뒤에 본다.

### 메뉴를 누르면 또 다른 새 탭이 열린다

탭이 두 번 늘어난다.

    수임처에서 회계를 누름   -> 새 탭 1  (smarta/account?wehagoT&cNum=...)
    메뉴에서 전자세금계산서   -> 새 탭 2  (smarta/account/SAAC0103?...&cd_com=...)

전표 목록은 **탭 2** 에 있다. 탭 1 만 들여다보면 아무리 기다려도 못 찾는다.
탭 제목이 `전자세금계산서(2기) - 오벨피부과의원` 인 그 탭이다.

메뉴를 누른 뒤에는 **모든 탭을 훑어** 주소에 `SAAC0103` 이 든 것을 찾아야 한다.
그 탭이 정말 그 고객사인지 `cd_com` 이나 `cNum` 으로 대조한다.

한 고객사에 탭이 둘씩 쌓이므로 마치면 **둘 다 닫아야 한다.**

### 화면에 들어간 뒤에도 조회를 눌러야 자료가 뜬다

전자세금계산서 화면에 들어가는 것과 자료가 뜨는 것은 다른 일이다.
사람이 하는 차례는 이렇다.

    기간을 확인하고 엔터
    구분을 2.매입 으로
    자료는 1.국세청 그대로 엔터
    거래처는 전체거래처 그대로 엔터
    조회 단추를 누른다

**구분은 늘 `1. 매출` 로 열린다.** 앞서 쓰던 값이 남아 있지 않다.
매입으로 바꾸지 않고 조회를 누르면 우리가 볼 자료가 안 나온다.

조회 줄의 생김새는 이렇다.

    (74,135)  2026.01.01     기간 처음
    (203,135) 2026.09.04     기간 끝
    (369,135) 1. 매출        구분   <- 눌러서 2. 매입 으로 바꾼다
    (489,135) 1. 국세청      자료
    (650,135) 전체거래처      거래처
    (899,144) 조회

자리는 창 크기에 따라 달라지므로 박아두지 말고 글자로 찾는다.
`조회 상세검색 열기` 같은 것이 함께 잡히므로 글자가 딱 `조회` 인 것만 쓴다.


## 이미 전송된 줄은 일괄변경이 받아주지 않는다

순회 중에 '일괄변경할 대상이 없습니다' 가 떴다. 체크도 됐고 유형 칸도 잡았는데 그랬다.
그 줄들이 이미 전송된 것(`ty_jungstat=2` 전표확정)이었다.

    1  확정가능
    2  전표확정   <- 이미 전송됨. 일괄변경이 받지 않는다
    5  미추천

애초에 전송된 줄은 건드려서도 안 된다. 대상에서 뺀다.
몇 건을 뺐는지는 기록에 남긴다.


## 조회 기간은 달력으로만 넣을 수 있다

기간 칸은 평소에는 글자다.

    <div class="fake_inputbox"> <span class="fakeinput">2026.01.01</span> </div>

누르면 그 div 에 포커스가 가고, 글자를 치면 `<input class="LSinput">` 로 바뀐다.
`____-__-__` 꼴 마스크가 걸려 있다. 그런데 **글자로는 넣을 수 없다.**

    한 자씩 천천히 치기      -> 안 들어감 (2026-2_-__ 로 어그러지기도 했다)
    값을 직접 넣고 알리기     -> 넣어도 되돌아감

불공제사유 라디오와 같다. 부품이 제 상태를 따로 들고 있어 바깥에서 넣은 값을 무시한다.

**달력을 쓴다.** 달력 하나에 시작과 끝이 나란히 뜬다.

    왼쪽(시작)   이전년  이전달  [2026.01]  다음달  다음년
    오른쪽(끝)   이전년  이전달  [2026.09]  다음달  다음년
    아래         취소  확인

단추는 글자로 알아본다. `이전달` 의 class 는 `btn btn_prev_mon` 이라
`month` 로 찾으면 안 걸린다. 겉으로는 글자가 안 보이지만 `innerText` 에는 있다.

달력틀은 `.LUX_smart_calendar` 로 찾고 가로 자리로 왼쪽 오른쪽을 가린다.
`.LUX_calendar` 가 같은 자리에 겹쳐 있으니 하나만 골라야 한다.

**날짜 칸에는 지난달 끝자락이 붙어 있다.** 첫 줄의 28, 29, 30, 31 이 그것이다.
그러니 몇째 칸인지로 세면 안 된다. **처음 나오는 1 이 이달 1일**이고
거기서부터 세어야 한다.


## 고객사에 따라 안내 창이 화면을 가린다

전자세금계산서 화면에 들어가거나 조회를 누를 때 안내 창이 뜨는 고객사가 있다.
그대로 두면 달력도 안 열리고 아무것도 못 한다.
'달력이 두 개로 안 보임 (0개)' 이 그것이었다.

화면에 닿은 뒤, 조회를 누른 뒤에 안내 창을 찾아 확인을 눌러 닫는다.
다만 **우리가 다뤄야 할 창은 건드리면 안 된다.**
글에 변경항목, 불공제사유, 일괄변경 하시겠, 계정과목 이 들어 있으면 그냥 둔다.

## 이름이 든 줄이 여럿인 고객사가 있다

수임처에서 이름으로 찾으면 줄이 둘 이상 걸리는 곳이 있다.
폐업 건이나 회계 전용 줄이 따로 있는 곳이 그렇다.

하나만 걸릴 때만 누르면 그런 고객사는 손도 못 댄다.
하나씩 눌러보고 **주소의 `cNum` 이 맞는 화면이 열릴 때까지** 해본다.
엉뚱한 곳이 열리면 그 탭은 닫고 다음 줄을 눌러본다.


## 지키는 것

- 전송(F3)은 절대 부르지 않는다. 전송은 사람이 한다.
- 칸마다 거래처명과 공급가액을 대조하고 다르면 건너뛴다.
- 쓰기 전후 코드를 비교해 실제로 바뀌었을 때만 성공으로 센다.
- 한 칸 먼저 하고 확인한 뒤에 나머지로 넘어간다.
- 한 칸이라도 실패하면 즉시 멈춘다.
